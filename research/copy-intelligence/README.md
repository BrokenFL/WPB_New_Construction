# Copy Intelligence Research Framework

This folder is the research and editorial planning layer for the West Palm Beach new-construction property pages.

## Purpose

Use these briefs to turn each project page from a basic data/card entry into a researched, buyer-facing building profile. The goal is to preserve factual discipline while improving the page voice, structure, and usefulness for luxury condo buyers.

## Working Method

1. Start with the existing project inventory in `WEST_PALM_BEACH_PROJECT_BUILDINGS.md`.
2. Verify facts against official developer/sales material first.
3. Use reputable reporting only where official material is thin, outdated, or silent.
4. Separate sourced facts from editorial interpretation.
5. Keep reusable firm/person research in `people-and-firms/` so repeated teams are not researched from scratch for every page.
6. Write implementation notes so Codex can update the correct site data, page copy, SEO copy, and buyer-facing sections without guessing.

## Folder Structure

- `buildings/` — one copy brief per building or combined project where twin towers share one marketing identity.
- `people-and-firms/` — reusable background on developers, architects, interior designers, hospitality brands, sales teams, and notable principals.
- `implementation-plan.md` — recommended order of operations for turning these briefs into site changes.

## Editorial Standard

Each page should answer five questions quickly:

1. What is the building?
2. Why does it matter in the West Palm Beach market?
3. Who is behind it?
4. What lifestyle does it actually sell?
5. What should a buyer understand before comparing it to nearby projects?

Avoid generic luxury filler. Use specific amenities, design authorship, location logic, delivery/status confidence, and buyer-relevant distinctions.

## Compliance Notes

- Do not imply guaranteed views, finishes, timing, pricing, or amenities unless official material supports it.
- Prefer phrasing such as "developer materials describe," "official site positions," or "currently marketed as" when details may change.
- Keep fair-housing language neutral and location/amenity based.
- Where developer disclaimers are important, preserve them in source notes rather than laundering marketing copy into hard claims.
