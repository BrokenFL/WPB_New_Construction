# Project Page Editorial Audit Checklist

Use this checklist before treating any project page as buyer-ready.

## Typography

- Hero headline can be large, but it should not force awkward one-word stacks on desktop or mobile.
- Section headlines should be elegant and clearly smaller than the hero.
- Card headlines should not compete with section headlines.
- Body text should stay readable at normal paragraph scale.
- Metadata, source confidence, category labels, image credits, and team labels should be visually secondary.
- Avoid repeating giant serif headline blocks in every module.

## Copy Repetition

- Define one job per section: intro, buyer lens, residences, amenities, location, team, coverage, CTA.
- Remove repeated use of the same prestige words across adjacent modules.
- Keep copy specific to the building, not generic luxury language.
- Use buyer questions and decision criteria instead of brochure claims.

## Image Fit

- Hero should show building identity, exterior, skyline, or site context.
- Residences should show interiors, balcony, view, kitchen, bath, or living space.
- Amenities should show lobby, pool, spa, wellness, service, lounge, or operations.
- Location should show map, corridor, waterfront, or neighborhood context.
- Team should use approved logos/headshots only; otherwise use restrained placeholders.
- News cards should use article-specific or project-specific imagery.
- Do not reuse the same image repeatedly in adjacent modules unless intentionally approved.

## Project Team Bios

- Confirm developer, co-developer/partner, architect, interior designer, landscape designer, brand/hospitality partner, and sales/marketing team if public.
- Use official or credible sources only.
- Keep each card concise: role, name, "Who they are," and "Why it matters for buyers."
- Mark uncertain roles as `needs-source-confirmation`.
- Preserve source URLs in the research/source docs or structured data.

## Source Confidence

- Preserve conflicts instead of smoothing them away.
- Keep address, residence count, pricing, delivery, fees, and service inclusions source-aware.
- Treat pricing, availability, incentives, and completion timing as verification-needed unless confirmed in current materials.

## Related Articles

- First show articles where `primaryProjectSlug`, `relatedProjectSlugs`, or `relatedProjectIds` matches the project.
- Then show corridor or project-family coverage only when directly relevant.
- Avoid unrelated generic news unless there are no project-specific or corridor-relevant articles.
- Each card should show headline, date, short deck, category, and `Read Update`.
- Article pages should link back to related project pages.
- Keep original external source links in article footers, not as primary project-page CTAs.

## CTA

- Hero CTA should request current availability or current packet.
- Mid-page links should support the section job: floor plans, amenity details, team/resources, or map context.
- Bottom CTA should ask the buyer to contact Brooke with current availability/floorplan questions.
- Avoid competing CTA actions inside news cards unless there is a clear buyer intent reason.

## Mobile Layout

- Check 390px width minimum.
- Confirm headings do not overflow or create excessive one-word stacking.
- Confirm cards, map panels, nav chips, and forms remain tappable.
- Confirm image crops show the subject, not empty sky/wall/floor.
- Confirm no text overlaps with images, sticky nav, or CTA buttons.
